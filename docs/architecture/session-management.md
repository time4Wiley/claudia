# Session Management

Session management in [[Claudia]] provides persistence, resumption, and organization of [[Claude Code CLI]] conversations.

## Overview

Sessions represent individual Claude Code conversations with their complete history, allowing users to:
- Resume previous conversations
- Track conversation history
- Organize by project
- Navigate timelines

## Session Storage

### File Structure
```
~/.claude/
├── projects/
│   ├── {encoded-project-path}/
│   │   ├── {session-id}.jsonl    # Session messages
│   │   └── ...
│   └── ...
├── todos/
│   └── {session-id}.json         # Todo state
└── checkpoints/
    └── {project-id}/
        └── {session-id}/
            └── {checkpoint-id}/  # Snapshots
```

### Session Identification
- **Session ID**: UUID generated by Claude Code
- **Project ID**: Encoded project path
- **Project Path**: Original filesystem path

## Session Lifecycle

### 1. Creation
New session started via:
```typescript
api.executeClaudeCode(projectPath, prompt, model)
```

Creates:
- New JSONL file for message storage
- Process registry entry
- Event listeners

### 2. Loading
Existing session resumed via:
```typescript
api.loadSessionHistory(sessionId, projectId)
```

Loads:
- Historical messages from JSONL
- Todo states if present
- Checkpoint metadata

### 3. Continuation
Resume conversation via:
```typescript
api.resumeClaudeCode(projectPath, sessionId, prompt, model)
```

Uses `--resume` flag to continue in same context.

## Session Features

### Message History
- Complete conversation stored in JSONL
- Each line is a complete JSON message
- Preserves tool invocations and results

### State Tracking
```typescript
interface Session {
  id: string;
  project_id: string;
  project_path: string;
  todo_data?: any;
  created_at: number;
  first_message?: string;
  message_timestamp?: string;
}
```

### Active Session Detection
System checks for running sessions:
1. Query [[ProcessRegistry]] for active processes
2. Match by session ID
3. Reconnect event streams if active
